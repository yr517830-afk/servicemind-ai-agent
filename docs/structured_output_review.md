# 结构化输出为何优于自由文本

## 核心结论

自由文本适合聊天和内容创作，但业务系统需要稳定、可验证、可编程处理的结果。结构化输出通过预先定义的数据模型，约束模型返回固定字段和类型，使输出能够直接进入数据库、接口和后续业务流程。

一个可靠的 LLM 业务链路可以概括为：

```text
Prompt 说明任务
    ↓
Schema 约束输出
    ↓
程序执行校验
    ↓
Fallback 处理失败

## Prompt：说明模型应该完成什么任务

Prompt 用自然语言告诉模型任务目标、业务背景和判断规则。例如，ServiceMind 的意图提取 Prompt 会要求模型分析客户消息，并识别业务意图、风险等级和判断依据。

一个清晰的 Prompt 通常包含：

- 模型扮演的角色
- 需要完成的任务
- 可使用的标签范围
- 业务判断规则
- 输入内容和必要上下文

但是 Prompt 只是指令，不能独立保证输出稳定。模型仍可能增加解释文字、遗漏字段、返回错误类型，或者使用系统没有定义的标签。因此，Prompt 负责说明“要做什么”，Schema 负责检查“结果是否合格”。

## Schema：规定系统能够接受什么结果

Schema 把模型输出转换成明确的数据契约，规定字段名称、数据类型、必填项和可选值。ServiceMind 使用 Pydantic 模型约束意图提取结果，例如：

```json
{
  "intent": "refund",
  "risk": "medium",
  "confidence_reason": "客户明确提出退款申请"
}
```

Schema 可以检查：

- 是否包含所有必填字段
- 字段类型是否正确
- 意图是否属于允许的枚举值
- 风险等级是否符合预定义范围
- 是否出现系统不接受的额外字段

通过校验后，程序可以安全读取 `intent` 和 `risk`，执行路由、工单分配或风险升级，而不需要从一段自由文本中再次猜测模型含义。

Schema 解决的是格式和类型可靠性，但不能保证业务判断一定正确。例如，模型可能返回格式完全合法的 JSON，却把退款错误识别为物流问题。因此还需要评测集监控语义准确率，并通过 Fallback 处理无法通过校验或无法安全执行的结果。

## Fallback：在模型失败时保证业务仍可继续

即使 Prompt 和 Schema 都设计正确，模型调用仍可能因为非法响应、拒答、限流或输入过长而失败。Fallback 的职责是把技术异常转换成明确、安全且可执行的业务动作，而不是直接把错误暴露给用户。

ServiceMind 为不同故障配置不同策略：

- 结构化响应非法：使用基础规则继续判断
- 模型拒绝处理：建议转接人工客服
- API 请求被限流：提示用户稍后重试
- 输入内容过长：要求保留订单号和核心问题后重新发送

Fallback 还应返回统一的故障代码、用户提示、降级动作和是否允许重试。这样前端、API 和日志系统可以使用同一套信息处理失败。

如果没有 Fallback，一次模型异常就可能中断整个业务流程；加入 Fallback 后，系统虽然不能保证每次都获得最佳答案，但能够保证失败是可识别、可解释和可恢复的。

## 自由文本与结构化输出对比

| 对比维度 | 自由文本 | 结构化输出 |
| --- | --- | --- |
| 输出格式 | 内容和表达方式不固定 | 字段和类型预先定义 |
| 程序处理 | 需要再次解析或匹配文本 | 可以直接读取字段 |
| 错误发现 | 难以自动判断结果是否完整 | 可以通过 Schema 自动校验 |
| 测试方式 | 结果变化大，断言困难 | 可以对字段和值编写稳定测试 |
| 系统集成 | 容易因措辞变化破坏流程 | 适合 API、数据库和工作流 |
| 失败处理 | 通常只能返回通用错误 | 可以根据故障类型执行 Fallback |

结构化输出的优势不是文字质量更高，而是把模型的不确定性限制在系统能够检查和处理的范围内。它让 LLM 从一个只会生成文字的组件，变成可以参与可靠业务流程的受约束服务。

## 2 分钟面试表达

在 LLM 业务系统中，我更倾向于使用结构化输出，而不是直接处理自由文本。

自由文本虽然自然，但格式不稳定。模型可能增加说明、遗漏字段或者改变措辞，程序很难可靠地解析。结构化输出则通过 Prompt、Schema 和 Fallback 建立三层保障。

首先，Prompt 负责说明模型要完成的任务、业务规则和可使用的标签。其次，Schema 规定固定字段、类型和枚举范围，并通过 Pydantic 校验结果是否可以被系统接受。最后，如果模型返回非法结构、拒绝处理、触发限流或者输入过长，Fallback 会把异常转换成规则判断、稍后重试、缩短输入或转人工等业务动作。

在 ServiceMind 项目中，我用这一方案提取客户意图和风险等级，并把结果接入路由、测试和评测流程。同时，我也认识到格式合法不代表语义一定正确，所以还建立了独立评测集，统计意图准确率、风险准确率和错误样本。

因此，结构化输出的真正价值不是让模型永远正确，而是让模型结果可以被校验、测试、监控和安全降级，从而可靠地参与实际业务流程。
